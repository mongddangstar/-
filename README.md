# 🧭 여행 코스 추천 (Trip Course Recommender)

여행 기간·이동수단·숙소·취향을 입력하면 **인기 장소 + 여행 스타일 + 동선**에 더해,
**여행 기간 중 열리는 특별 행사**까지 고려해 일자별 코스를 추천하는 단일 파일 웹앱입니다.

> 열어보기: 브라우저에서 **`index.html`** 을 그대로 열면 됩니다. (설치·빌드 불필요)

## 특징
- **초기 정보 등록 폼**: 여행지 / 기간 / 출발 시각·장소·소요시간 / 이동수단(대중교통·자차) / 숙소 / 동행 / 스타일(복수 선택) / 복귀 시간대.
- **문장으로 쓰는 자유 입력(프롬프트형)**: 한 줄에 하나씩, **자연어 문장 그대로** 적어도 됩니다. 앱이 문장에서 **실제 장소명만 뽑아내고**(예: `교동짬뽕을 먹으러 갈 거야` → `교동짬뽕`), 맥락을 해석합니다.
  - **도착 시점 인식**: `도착하자마자`·`도착 후`는 첫날 도착 직후로 고정 배치.
  - **시각 인식**: `오후 3시`, `15시`, `저녁 7시 반` 같은 시각을 알아채 그 시간에 배치합니다(문장에 시각이 여러 개면 마지막 것 기준).
  - **추천/질문형 요청 인식**: `가볼만한 명소 1~2개 넣어줘`, `저녁 먹을 만한 맛집 어디 없을까`처럼 추천을 요청·질문하면 문장을 통째로 넣지 않고, 해당 유형의 인기 장소를 **골라서** 코스에 편입(내장 데이터가 없는 여행지는 안내 문구로 알려줌).
  - 여러 장소·나열·부정도 인식: `칠성조선소 갔다가 3시반 청초호에 왔어`(→ 각각 시각 배치), `중앙시장과 아바이마을`(→ 둘로), `아직 ~ 가지 않았어`(→ 방문 대상). 줄임말도 내장 장소와 자동 매칭(`중앙시장`=`속초관광수산시장(중앙시장)`)해 **중복 없이** 넣습니다. `@지역`·`#맛집`/`#카페`/`#명소` 태그를 직접 붙여도 인식합니다. 입력한 곳은 전부 넣지 않고 **동선에 맞는 것만 골라** 배치하며, 동선 밖은 제외 사유를 알려줍니다.
- **자유 프롬프트 일정 고정**: `둘째날 오후 해수욕장`, `셋째날 오전 호텔 수영장`처럼 날짜·시간대를 함께 적으면 그 시점에 **고정 배치**합니다.
- **같은 시간대 겹침 → 선택지 제안**: 두 곳 이상이 같은 시각에 겹치면 한 줄로 쌓지 않고 **‘한 곳을 골라보세요’ 선택지**로 묶어 보여줍니다. 원하는 곳을 탭하면 선택되고 나머지는 대안으로 흐려집니다.
- **Claude가 만든 코스 불러오기(연동)**: Claude(챗)에게 여행을 자연어로 설명하면, Claude가 이해·계산한 코스를 담은 링크(`#d=…`)를 만들어 줍니다. 그 링크를 열면 앱 입력·코스가 **그대로 채워집니다**(구조화 코스 `fpParsed`를 실어 규칙 재파싱 없이 사용). 입력칸을 직접 수정하면 앱 기본 해석으로 되돌아갑니다.
- **메뉴 다양화**: 식사 추천 시 같은 메뉴(예: 물회)가 반복되지 않도록 요리 종류를 분산합니다.
- **기기 내 저장 & 기기 간 이동**: 입력·코스를 브라우저에 자동 저장(localStorage)하고, ‘🔗 다른 기기로 가져가기’로 상태를 담은 링크(`#d=…`)를 만들어 메일/메신저로 옮기면 다른 기기에서 그대로 복원됩니다. (서버 없는 정적 앱이라 계정 로그인 기반 클라우드 동기화 대신 링크 방식 사용)
- **국내외 어디든**: 특정 지역 전용이 아니라 여러 여행지(해외 포함)에 쓰도록 설계. 내장 추천 DB가 있는 여행지(현재 속초)는 큐레이션 장소를 함께 쓰고, **그 외 여행지는 직접 추가한 장소 위주**로 코스를 구성합니다(속초 데이터로 대체하지 않음). 2단계 질문의 야외활동 문항도 여행지에 맞게 문구가 바뀝니다. 결과의 각 장소에 **네이버지도·구글맵스** 링크를 함께 제공합니다.
- **저장 위치**: 코스를 만든 뒤 **결과 화면 하단**에서 저장/기기 이동(🔗 링크 복사)·초기화를 할 수 있습니다.
- **출발/도착 시각**: 출발 시각·이동 소요로 도착을 추정하거나, **도착 시각을 직접 입력**해 첫날 일정을 정확히 맞춥니다.
- **되묻는 질문 플로우**: 설악산 산행 의향, 짐 보관, 하루 이동 강도, 행사 포함 여부를 물어 정확도를 높입니다.
- **추천 엔진**: `인기도 + 스타일 매칭 + (숙소 기준) 동선 근접`으로 점수화하고, 하루를 지리적 구역(zone)으로 묶어 대중교통 이동을 최소화한 시간표를 만듭니다. 점심 12시·저녁 18시 앵커링으로 현실적인 타임라인을 생성합니다.
- **특별 행사 처리**: 여행 기간과 겹치는 행사를 자동으로 찾아 배너로 강조합니다. **강제로 넣지 않고**, "일정에 넣기 / 알려만 주기"를 사용자가 선택합니다.
- **대중교통 안내**: 각 장소 카드에 시내버스/도보 이동 안내와 네이버지도 링크를 제공합니다.
- **모바일·다크모드 대응**: 여행지에서 폰으로 바로 보기 좋게 반응형·테마 대응.

## 데이터 정책
- 인기 장소: **최근 1~3년** 여행 자료(대한민국 구석구석·트립닷컴·식신·다이닝코드·블로그 등)를 참고해 큐레이션.
- 특별 행사: 단기 이벤트 특성상 **1년 이내** 자료만 반영 (예: 2026 속초 썸머 페스티벌, 7/31~8/2).
- 각 항목에 근거/최근성 메타를 표기합니다.

## 실시간 크롤링 확장 (향후)
유튜브·인스타그램·네이버블로그의 실시간 수집은 API 키·이용약관·네트워크 정책 이슈로
현재 버전에는 포함하지 않았습니다. 대신 `index.html` 내 **`dataSources`** 객체에 확장 지점을 스텁으로 남겨두었습니다.

| 소스 | 방식 | 비고 |
|---|---|---|
| YouTube | Data API v3 검색 (`publishedAfter`로 최근 1~3년) | API 키 필요 |
| 네이버 블로그 | 네이버 검색 API (`/v1/search/blog`) | Client ID/Secret 필요 |
| 네이버 지도 | 지역 인기 장소(국내) 수집 → `fetchNaverMap` | 서버(프록시) 연동 필요, CORS로 정적 크롤링 불가 |
| 구글맵스 | Places API Text/Nearby Search(해외) → `fetchGoogleMaps` | 서버 키 연동 필요 |
| 지역 행사 | 공공데이터포털 / 한국관광공사 TourAPI | 서비스 키 필요, 1년 이내 필터 |
| 인스타그램 | 공식 공개 콘텐츠 API 부재 → **수동 큐레이션 권장** | 스크래핑은 이용약관 위반 소지 |

각 어댑터를 구현해 결과를 `places` / `events` 배열로 병합하면 자동으로 추천에 반영됩니다.
